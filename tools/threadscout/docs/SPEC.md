# ThreadScout — спецификация 0.1

Дата: 18 сентября 2026. Владелец: Alexey Grigorev. Это первый локальный прототип, а не готовый автономный сервис публикаций. Фактические ограничения платформ см. в [SOURCES.md](SOURCES.md); решения и числовые настройки ниже — предлагаемый дизайн.

## 1. Цель и нецели

Сократить поиск подходящих разговоров до одной небольшой подборки. Ориентир: 5–10 минут личного участия в день, не обязательная ежедневная норма комментариев. Предпочитать вопросы, на которые есть проверяемый полезный вклад. Возможность вставить ссылку оценивается отдельно от тематической релевантности.

Нет покупки мониторинга, платного API-fallback, новой машины, генерации публичных HN-комментариев, автоматических постов, голосований, холодных личных сообщений, фарминга кармы, имитации «человеческого» поведения и обхода ограничений.

Желаемый конечный UX — пользователь пишет и явно подтверждает отправку в Telegram. **В 0.1 реализована подготовка, а не доставка комментария на площадку.** Открытие сайта на последнем шаге пока необходимо. Это самостоятельная незавершённая интеграция, не скрытая кнопка публикации.

## 2. Путь пользователя

1. Бот показывает максимум три новые карточки за подборку, не более одной из одной ветки в этой подборке.
2. Карточка содержит источник, исходный фрагмент, причину совпадения с профилем, вопрос к личному опыту и уровень проверки контекста.
3. «Контекст» обновляет источник. HN: цель, до шести родителей и четыре непосредственных ответа. Это ограниченная выборка, не утверждение, что вопрос ещё никем не решён.
4. «Почему я» даёт приватную справку и до трёх существующих материалов. Codex включается только по этой кнопке и только локальной настройкой.
5. «Написать самому» привязывает следующий ответ на конкретный ForceReply к нужной ветке. В БД поле `human` изначально пустое. AI-текст туда не подставляется.
6. Опциональный Mini App показывает отдельно оригинал/контекст и редактируемое поле собственного ответа. «Сохранить» и «Скопировать» — разные действия. Автоматически пересылать содержание в Reddit/HN он не умеет.
7. «Пропустить», «Завтра», «Готово» сохраняют решение. Последнее не выдаётся за проверенную публикацию.

Нативная Telegram CopyTextButton ограничена 256 символами. Более длинные ответы копируются из блоков или Mini App; доступ к clipboard зависит от клиента. Авторизация Mini App проверяется сервером по HMAC и давности initData, а не по присланному без подписи user ID. [S13–S14]

## 3. Публичный текст и HN

Правила HN запрещают сгенерированный и AI-отредактированный текст. Сценарий «AI написал → слегка поправил → скопировал» не считается здесь допустимым решением. [S07]

Разрешённая в нашем дизайне роль модели: приватно указать совпадение темы с известными материалами и спросить автора о конкретном факте из его опыта. Не писать фразы от его лица, не формулировать аргумент для публикации, не переводить/редактировать его HN-ответ. Это консервативный выбор реализации, а не официальная гарантия со стороны HN.

У Reddit правила сообществ могут отличаться; текущая версия также оставляет публичное авторство человеку. Сборщик не объявляет саморекламу разрешённой, когда правила не проверены.

## 4. Архитектура

```text
HN Algolia ──── официальный HN item API ──┐
                                        ├─ SQLite → правила отбора → Telegram
Reddit approved OAuth [OFF by default] ──┘                  │
                                            Codex CLI [optional, private notes]
                                                           │
                                                собственный ответ / Mini App
                                                           │
                                                  ручная публикация вне 0.1
```

`core.py`: модель Item, URL allowlist, HTML-to-text, SQLite и matching.
`sources.py`: ограниченные read-only сборщики и актуализация.
`app.py`: Telegram long polling, команды, расписание, bounded worker.
`codex.py`: локальный CLI, структурированная справка, валидация ссылок через asset ID.
`webui.py` + `editor.html`: опциональный редактор, подписанная Telegram-сессия.

Сторонних Python-пакетов в базовой версии нет. SQLite здесь хранит состояние; твой SQLiteSearch не требуется как зависимость. Его добавление для каталога большого числа статей имеет смысл только после проверки базового отбора.

## 5. Сбор и оценка

HN: девять запросов, максимум две страницы по 30 совпадений на запрос; паузы между запросами. Поисковый индекс может отставать и не гарантирует полноту. Firebase проверяет актуальность выбранного объекта. [S08–S09]

Reddit: с письменным разрешением и OAuth-токеном — последние 50 публикаций и 50 комментариев в каждом настроенном сообществе. Это не полный поиск. Автоматическое обновление access token пока отсутствует. При отказе/истечении токена — ошибка, не fallback на `.json`, RSS, old.reddit или Computer Use. Требования доступа не исчезают из-за самостоятельной разработки. [S16]

Правила 0.1: до 44 баллов за тематические совпадения, 18 за признаки вопроса/потребности, 42 за упоминание проекта, до 12 за свежесть; сумма ограничена 100. Без темы/упоминания — ноль. Порог 35. Эти числа — стартовая эвристика, не вероятность успеха или оценка человека.

Список собственных ресурсов выбирается только из `profile.json`; модель не может добавить произвольный asset ID. Совпадение ресурса не означает рекомендацию вставить ссылку. Не выводить чувствительные характеристики участников и не связывать их с внешними профилями.

## 6. Данные, очередь и ошибки

Item: `key`, `platform`, `url`, `title`, `text`, `created`, `thread`, `community`, `context`, `checked`, `available`, `demo`.

Состояния: `new`, `skip`, `done`; отдельные `notified` и `wake`. Upsert сохраняет пользовательское решение. Отложить — вернуть `new`, разбудить через 24 часа. Повторные команды `/digest` могут показать следующую тройку: жёсткий общий дневной лимит пока не реализован.

Draft: только `human`, версия. Mini App использует optimistic concurrency: устаревшая версия не перетирает новый текст. ForceReply привязан к конкретной карточке. `/cancel` удаляет все старые привязки.

Raw items, черновики и связанные справки хранятся локально 7 дней по времени первого получения. Это осознанный компромисс: экспортировать собственный важный текст до истечения срока. Tombstones и история решений — 90 дней без исходного текста. При удалённом источнике локальный текст и кэш справки очищаются при следующей проверке.

**Это не удаляет уже отправленные сообщения из Telegram.** Полный цикл удаления копий в Telegram, проверка удалений всех сохранённых объектов и договорные сроки хранения — задача до постоянной Reddit-эксплуатации. Базовый TTL не является заявлением о достаточном соблюдении всех условий Reddit.

Статус различает «источник выключен», «нет совпадений» и «сбор не удался». HTTP ошибки не раскрывают токен-содержащие URL. Отправка карточки отмечается после успешного Telegram-ответа; при сетевой неопределённости возможен дубликат. Гарантии exactly-once нет.

Расписание выполняется внутри локального процесса, при сне не работает. Одна попытка плановой подборки после заданного часа, возможен запуск сразу после позднего включения. Очередь тяжёлых задач ограничена восемью, одинаковые активные задачи не множатся. Локальный порт 8766 блокирует второй `run`.

## 7. Безопасность и Codex

Личный Telegram chat ID и sender ID должны совпасть с единственным `TELEGRAM_OWNER_ID`. Группы и другие пользователи игнорируются. Новый отдельный токен; существующий webhook бот не удаляет.

Codex запускается во временной папке, с read-only sandbox, отключёнными shell/unified-exec/web-search и без пользовательской конфигурации. Принудительная ChatGPT-авторизация; переменные токенов/секретов удаляются из дочернего окружения. `auth.json` остаётся в штатном локальном хранилище Codex; его нельзя копировать в репозиторий или CI. Таймаут 100 секунд, ограничение размера вывода, фиксированная JSON-схема. [S10–S12]

Это снижение риска, а не доказательство полной изоляции всех версий Codex: актуальные флаги и доступные инструменты проверяются локально до включения. При отказе CLI остаётся deterministic matching. Не снимать ограничения ради обхода ошибки. Reddit-контент не передаётся Codex без отдельного подтверждения `REDDIT_LLM_APPROVED`, покрывающего этот сценарий.

Mini App слушает только `127.0.0.1:8765`, HTTPS обеспечивается внешним tunnel. Сервер проверяет Origin, HMAC initData, TTL и владельца. Это персональный прототип, не публичный production-хостинг. Токены, БД, пользовательские ответы и журналы не должны попасть в публичный research-dump.

## 8. Как достроить отправку строго по нажатию

**План, не готовая функция.** Человек пишет окончательный текст. Перед подтверждением показываются площадка, аккаунт, parent ID, полная версия текста и точная ссылка назначения. Approval привязан к хэшу текста, версии, одноразовому nonce и сроку, например пять минут. Изменение текста или назначения аннулирует approval.

Reddit: сначала разрешение на конкретный read/write сценарий, корректный тип аккаунта, OAuth с минимальными правами, проверка правил/архива/блокировки. Затем отдельный publisher, а не расширение инструментария модели. HN: официальный API документирует чтение, не публикацию; Computer Use/браузерный адаптер нужно отдельно проверить на локальной установленной версии и текущих условиях площадки. Отсутствие write API не равно запрету любого ручного браузерного действия, но не даёт готовой интеграции. [S07–S08,S16]

Одно нажатие должно отправлять ровно один утверждённый комментарий. Нельзя автоматически повторять POST после таймаута: сначала сверить, не появился ли уже ответ. При CAPTCHA, блокировке, недоступном аккаунте или неподтверждённом результате — остановиться. Никаких обходов, голосований или сопутствующих публикаций.

## 9. Следующие функции и критерий полезности

Первая очередь разработки: живой запуск HN/Telegram/Codex, мобильный тест редактора, проверка runtime-инструментов Codex. Затем — легитимный Reddit-доступ, OAuth refresh, соседние ответы/правила и удаление копий.

Позже: слежение за ответами на собственные комментарии; причины отклонения и адаптация фильтров; каталог собственного блога через подтверждённый RSS; ручная очередь публикаций статей; контролируемая отправка из Telegram. Ничего из этого не считается готовым в 0.1.

Пилот: измерять долю карточек, которые действительно полезны, время участия, содержательные продолжения, удаления/замечания модераторов. Карма и число размещённых ссылок не являются целевыми метриками. Порог качества подбирать по фактической обратной связи, не по обещаниям конверсии.
