# Hooked — Action Checklist

**Nir Eyal, with Ryan Hoover · English reading/listening companion · Source-linked, summary-based edition**

Actions reconstructed from summaries of *Hooked: How to Build Habit-Forming Products*, with matching methods corroborated by Eyal's articles. This is not an official workbook or a verified inventory of every instruction in the original.

**Edition note:** the supplied cover advertises an updated edition and an additional case study. This checklist covers the eight core chapters available in the consulted summaries; the additional edition-specific case study has not been independently reconstructed. Chapter titles follow the chapter-organized summary. [HH]

**Use:** mark completed actions with `- [x]`. **Practice** adapts reported advice; **Reflection** is a decision; **Option** is an alternative or a clearly identified case-study adaptation. Labels and task splitting are editorial. Design around a benefit users actually want, not engagement for its own sake.

## 1. The Habit Zone

- [ ] **Reflection:** Identify the beneficial recurring behavior your product should support. [HK]
- [ ] **Practice:** Estimate how often that behavior naturally occurs. [HK]
- [ ] **Practice:** Compare the product's perceived usefulness with the user's existing alternatives. [HK]
- [ ] **Reflection:** Decide whether habitual use is appropriate for this product at all. [HT]
- [ ] **Practice:** Identify the established routine a customer would need to change. [HB]
- [ ] **Practice:** Sketch one complete trigger → action → reward → investment cycle. [HS]
- [ ] **Reflection:** Explain why returning would help the user, not merely your retention metrics. [HS]

## 2. Trigger

### Understand the context

- [ ] **Practice:** Describe what happens immediately before someone needs your product. [HB]
- [ ] **Practice:** Identify the practical frustration or uncertainty behind that moment. [HS]
- [ ] **Practice:** Use successive why-questions to investigate the underlying motivation. [HS]
- [ ] **Practice:** Distinguish an external prompt from an internally remembered reason to return. [HK]
- [ ] **Practice:** Connect the prompt to the moment when the product is genuinely useful. [HB]

### Choose relevant external triggers

- [ ] **Option:** Use paid promotion to introduce a relevant audience to the product. [HK]
- [ ] **Option:** Seek earned attention through useful coverage or shareable work. [HK]
- [ ] **Option:** Enable a helpful invitation or recommendation between existing relationships. [HK]
- [ ] **Option:** Offer an opt-in reminder or other owned communication channel. [HK]
- [ ] **Practice:** Make the prompt's next action clear and easy to understand. [HB]
- [ ] **Practice:** Remove competing instructions that obscure the intended next step. [HB]
- [ ] **Practice:** Examine whether repeated value eventually produces returns without repeated advertising. [HB]

## 3. Action

### Reduce the obstacle to receiving value

- [ ] **Practice:** Identify the simplest action that moves the user toward the expected reward. [HS]
- [ ] **Practice:** Check motivation, ability, and the presence of an appropriate prompt. [HK]
- [ ] **Practice:** List the steps currently required to complete the action. [HB]
- [ ] **Practice:** Remove a step that does not contribute necessary value or protection. [HB]
- [ ] **Practice:** Assess the time required at the moment of use. [HK]
- [ ] **Practice:** Assess whether the monetary cost blocks the action. [HK]
- [ ] **Practice:** Assess the physical effort and attention the action requires. [HK]
- [ ] **Practice:** Check whether the action conflicts with the user's social context or existing routine. [HK]
- [ ] **Practice:** Simplify around the user's scarcest resource before increasing persuasive messaging. [HS]

### Examine the chapter's perception effects

- [ ] **Option:** Test clearer framing without changing or concealing the actual offer. [HH]
- [ ] **Reflection:** Check how an initial comparison or price anchors expectations. [HH]
- [ ] **Option:** Communicate a genuine supply limit without inventing scarcity. [HH]
- [ ] **Option:** Show real progress already made toward completing a task. [HH]

## 4. Variable Reward

- [ ] **Practice:** State what need the user expects the reward to satisfy. [HR]
- [ ] **Practice:** Check whether the experience actually satisfies that need. [HR]
- [ ] **Option:** Support meaningful social connection or recognition: rewards of the tribe. [HR]
- [ ] **Option:** Help users discover useful information or resources: rewards of the hunt. [HR]
- [ ] **Option:** Support mastery, competence, or completion: rewards of the self. [HR]
- [ ] **Practice:** Match the reward to the user's motivation rather than copying another product. [HS]
- [ ] **Reflection:** Identify where relevant variety already exists in the experience. [HR]
- [ ] **Reflection:** Check whether novelty will quickly exhaust itself after repeated use. [HS]
- [ ] **Option:** Enable useful contributions from other users where these create continuing value. [HS]

## 5. Investment

- [ ] **Practice:** Distinguish work that produces an immediate reward from work that improves future use. [HI]
- [ ] **Practice:** Ask for a small contribution after the user has experienced value. [HI]
- [ ] **Practice:** Explain how that contribution will make the next experience better. [HI]
- [ ] **Option:** Let users save or create content they will want to revisit. [HI]
- [ ] **Option:** Use relevant preferences or data to improve subsequent results. [HI]
- [ ] **Option:** Support valuable relationships or a trustworthy reputation over time. [HS]
- [ ] **Option:** Help users develop skills that make the product more useful. [HS]
- [ ] **Practice:** Increase requested effort gradually rather than demanding extensive setup immediately. [HI]
- [ ] **Practice:** Identify the future reminder or response the investment makes possible. [HI]
- [ ] **Practice:** Check that previous contributions remain useful on the next visit. [HI]

## 6. What Are You Going to Do with This?

- [ ] **Reflection:** Ask whether you would genuinely use the product yourself. [HS]
- [ ] **Reflection:** Ask whether using it materially improves the intended user's life. [HS]
- [ ] **Practice:** Use those answers to examine your position in the Manipulation Matrix. [HS]
- [ ] **Reflection:** Identify foreseeable ways repeated use could become harmful. [HE]
- [ ] **Practice:** Define a response to signs that users want to stop but struggle. [HE]
- [ ] **Practice:** Plan supportive interventions rather than treating all increased usage as success. [HE]
- [ ] **Practice:** Review whether the business benefits from behavior that harms its users. [HE]

## 8. Habit Testing and Where to Look for Habit-Forming Opportunities

### Identify → Codify → Modify

- [ ] **Practice:** Define a realistic repeat-use threshold for this particular product. [HT]
- [ ] **Practice:** Instrument relevant actions and their timestamps in a working product. [HT]
- [ ] **Practice:** Identify users whose behavior meets the chosen threshold. [HT]
- [ ] **Practice:** Compare cohorts to establish a retention baseline. [HT]
- [ ] **Practice:** Look for common sequences followed by the most consistently returning users. [HT]
- [ ] **Practice:** Interview those users about why the sequence matters. [HT]
- [ ] **Practice:** Turn the observed pattern into a hypothesis, not a causal conclusion. [HT]
- [ ] **Practice:** Modify onboarding to help suitable new users reach the same useful experience. [HT]
- [ ] **Practice:** Compare later cohorts to test whether the modification helped. [HT]
- [ ] **Practice:** Repeat the process as the product changes. [HT]

### Find new opportunities

- [ ] **Reflection:** Notice a recurring unmet need in your own routine. [HH]
- [ ] **Practice:** Investigate emerging behaviors among a small group of early users. [HH]
- [ ] **Practice:** Look for interface or technology changes that remove steps from an existing behavior. [HH]

## Interpretation and coverage

The framework is represented as a set of design hypotheses to test, not a guarantee of habit formation. A useful infrequently used product need not become habitual. Fixed “habit in X days,” “nine times better,” and habitual-user percentage claims are not used as universal targets. Behavioral correlations do not by themselves establish causation.

The author's articles corroborate investment, rewards, testing, and responsibility discussed in the book summaries; they are not presented as original-book excerpts. The gated workbook and the updated edition's extra case study were not accessed. Bookey's PDF at the plain `hooked.pdf` address concerns a different author's book and was excluded.

Implementation safeguards, not additional claimed book exercises: use opt-in notifications, allow easy stopping and data control, preserve promised functionality, and never fabricate scarcity or progress. Useful novelty is not an instruction to withhold basic service randomly. Usage data alone cannot diagnose an addiction; support should respect privacy and user choice. These safeguards clarify implementation rather than add invented author assignments.
