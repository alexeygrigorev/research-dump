## Main lesson (45–60 min)

1. **Hook (5 min).** Clone a participant's product, or a well-known one, live with an agent in minutes. The point to land is that features, code and UI are copied in an afternoon.
2. **What stopped being a moat (5 min).** Features, codebase, integrations alone, exportable data, speed alone. Use the table in [moat-catalogue.md](moat-catalogue.md).
3. **The four MicroConf 2026 views (10 min).**
   - Hewitt (US): first-party data, speed, relationships, vertical.
   - Eden (US): network effects, regulation, operational excellence, capex.
   - Walling (Europe): 10 attacks, 8 moats.
   - "Sell the outcome" (Europe): learning loop, outcome pricing.
4. **The small-founder moat stack (15 min).** Audience/distribution, then first-party outcome data, then trust and vertical focus. Work through the four-test check in [first-party-data.md](first-party-data.md): unseen, outcome-linked, compounding, sticky.
5. **Counterarguments (5 min).** a16z/NFX on why data isn't a moat by default. Incumbents own more data, so out-niche them rather than out-data them.
6. **Tactical hardening (5 min).** Server-side prompts and logic, rate limits, ToS. This is hygiene, not a moat.
7. **Workshop (10–15 min).** Each participant fills in the moat canvas.

## Deliverable: moat canvas (one page, peer-reviewed)

- **Clone test:** if a clone launched tomorrow at half price, why would my users stay?
- **Unseen data:** what data only my product will ever see, and how I capture its outcomes.
- **Audience:** the one owned channel I'm growing, with its current size and a 30-day target.
- **Trust/vertical:** the niche and the proof (case studies, results, a named human).
- **The moat I'm *not* claiming:** the honest list of features and code that anyone can copy.
- **Next 2 weeks:** one action that deepens one moat.

**Peer review rubric:** is each moat specific? Does it pass the clone test? Is the data claim checked against the four tests?
