# Запуск вечером и передача следующему агенту

## Что подготовить

- [ ] Доступ к своей локальной машине, Python 3.11+ и возможность держать процесс запущенным. На Windows проверить IANA timezone data; при необходимости использовать WSL или установить `tzdata`.
- [ ] Новый Telegram-бот через @BotFather (`/newbot`), токен только в локальной `.env`. Не использовать токен действующего writing assistant: иначе два получателя updates будут мешать друг другу.
- [ ] Свой числовой Telegram user ID: отправить `/start` новому боту и получить его через локальную команду `whoami`. Не включать регистрацию «первый написавший становится владельцем».
- [ ] Проверенный локальный `codex login status` с ChatGPT-auth. В эту сессию токенов не присылать, `auth.json` не переносить в проект.
- [ ] Просмотр `profile.json`: какие материалы ты действительно готов обсуждать, что бесплатно, что требует входа, какие личные факты можно раскрыть. Нынешний профиль собран только по публичным источникам.
- [ ] Выбор времени в `config.json`: сейчас 19:00 Europe/Berlin, до трёх карточек за подборку. Профили HN/Reddit и прозрачное описание своей связи с проектами нужны для реального участия, но не для HN-чтения.

## Минимальный запуск без модели и Reddit

```bash
git clone https://github.com/alexeygrigorev/research-dump.git
cd research-dump/threadscout
python3 -m unittest discover -s tests -v
python3 -m threadscout demo
cp .env.example .env
```

Отредактировать `.env`: сначала `TELEGRAM_BOT_TOKEN`, затем отправить боту `/start` и выполнить:

```bash
python3 -m threadscout whoami
```

Записать найденный собственный ID в `TELEGRAM_OWNER_ID`. Затем:

```bash
python3 -m threadscout doctor
python3 -m threadscout run
```

В Telegram: `/demo` → «Написать самому» → ответ на сообщение бота → «Мой текст». Затем `/scan`, дождаться состояния успешного сбора в `/status`, `/digest`. Тестовые вопросы не являются найденными реальными ветками. При первой сетевой ошибке не считать источники пустыми и не менять на обходной URL.

Без включённого `run` ежедневных подборок нет. Закрытие терминала или сон машины останавливают работу. Для постоянного режима следующему агенту подготовить user-service/launchd/Task Scheduler под твою ОС; установленного сервиса в 0.1 нет.

## Подключить Codex без нового API-счёта

Проверить текущую установленную версию и её `codex exec --help`. Выполнить `codex login` / `codex login status`; включить `USE_CODEX=1`, перезапустить процесс и нажать «Почему я» на HN-карточке. Убедиться, что результат — приватная справка, поле собственного ответа осталось пустым и не было вызова внешних инструментов. При несовместимом флаге обновить/адаптировать CLI по официальным документам, а не снимать sandbox. [S10–S12](SOURCES.md)

## Два поля внутри Telegram: опциональный Mini App

Базовые сообщения бота работают без публичного сервера. Редактору внутри Telegram нужен HTTPS URL. Для короткого личного теста можно использовать бесплатный Cloudflare Quick Tunnel; он временный и не является production-сервисом с гарантией доступности. Установить `cloudflared` по официальным инструкциям. [S21](SOURCES.md)

```bash
cloudflared tunnel --url http://localhost:8765
```

Скопировать выданный HTTPS origin в локальную `TELEGRAM_WEBAPP_URL`, без пути. В другом терминале из папки проекта:

```bash
python3 -m threadscout serve
```

Перезапустить `run`, заново получить карточку. Внутри Telegram открыть «Редактор: оригинал + мой ответ». Проверить на своём телефоне загрузку, сохранение, конфликт двух вкладок и clipboard. При смене временного tunnel URL обновить `.env`, перезапустить оба процесса и получить новую кнопку. Не открывать исходный порт напрямую наружу. Обычная вкладка браузера без подписанной Telegram-сессии не должна получать данные.

## Reddit — отдельная зависимость, не обещание на вечер

Зарегистрировать бесплатный Reddit Pro по [инструкции](RESEARCH.md), настроить темы и собственные Links. Не экспортировать чужие тексты из Pro.

Для автоматического источника сначала согласовать API и маркетинговый сценарий, включая хранение и Telegram. Затем получить подходящий read-only OAuth-токен; лишь после этого установить `REDDIT_APPROVED=1`, `REDDIT_ACCESS_TOKEN` и честный `REDDIT_USER_AGENT`. Для Codex — отдельная проверка права передачи, затем `REDDIT_LLM_APPROVED=1`. Refresh токена и полный lifecycle удаления дописать до постоянной работы. Одобрение нельзя получить переключением флага или гарантировать сегодня. [S16](SOURCES.md)

## Задание coding agent: порядок работ

**P0 — подтвердить живой базовый путь.** Прочитать AGENTS.md и SPEC.md, прогнать тесты, проверить актуальный Codex CLI и отсутствие доступных побочных инструментов. С твоими локальными настройками протестировать HN → Telegram → собственный ответ → сохранение. Проверить real-response схемы, 401/403/429, недоступную сеть и поведение при рестарте. Не публиковать ничего во время smoke test.

**P0 — телефон.** Проверить Mini App на конкретном Telegram-клиенте, HTTPS, signed initData, буфер и конфликт сохранений. При необходимости сохранить one-tap copy через более подходящий проверенный UI. Не копировать приватную AI-справку в HN-черновик.

**P1 — легитимный Reddit.** После подтверждения доступа реализовать OAuth refresh без паролей в исходниках, текущие rate-limit headers, соседние ответы и правила сообществ, проверку deleted/removed/locked/archived, удаление отправленных копий и нужные сроки хранения. Доступ в отказе не обходить.

**P1 — отправка по явному нажатию.** Реализовать отдельно по разделу 8 SPEC: точное назначение + текст + аккаунт + одноразовое подтверждение, инвалидируемое изменением текста. Сначала mock publisher, затем отдельно проверенный разрешённый live-адаптер. Для HN исследовать поддерживаемый установленным Codex Computer Use; Python CLI-авторизация сама по себе не означает доступ к desktop control. При невозможности подтвердить поведение оставить честный manual-open. Не объявлять эту задачу выполненной по одному наличию кнопки.

**P2 — качество мониторинга.** Отслеживание ответов на собственные комментарии, причины skip, обучение фильтров на решениях, пользовательский календарь digest, каталог собственных статей, ручная очередь размещения блога. Не вводить норму ссылок/комментариев ради активности.

## Отделить в собственный репозиторий

Копировать папку в новое место **до** появления секретов/данных либо исключить `.env`, `data/`, кэши и локальные сессии. Создать новый репозиторий `threadscout` на GitHub обычным способом, выполнить `git init`, проверить `git status --short`, добавить только исходники и docs, затем первый commit и push. Не делать `git add .` без просмотра содержимого.
